# Step 01 — Dependencies

## Objective

Install KaTeX and its TypeScript types, generate the pre-patched CSS constant module (`katex-css.ts`), and verify the import chain compiles cleanly before any plugin logic is written.

## What to Implement

### 1a. Install npm packages

Add to `package.json`:

```json
"dependencies": {
  "katex": "^0.16.0"
},
"devDependencies": {
  "@types/katex": "^0.16.0"
}
```

Run: `npm install`

Verify: `node_modules/katex/dist/katex.min.js` exists, `node_modules/katex/dist/fonts/` contains `.woff2` files, TypeScript picks up types from `@types/katex`.

### 1b. Create the font-inlining script: `scripts/inline-katex-fonts.mjs`

This script is a one-time (and re-run-on-upgrade) build utility. It:

1. Reads all `*.woff2` files from `node_modules/katex/dist/fonts/`.
2. Base64-encodes each file's buffer.
3. Reads `node_modules/katex/dist/katex.min.css`.
4. Replaces every `url(fonts/<filename>.woff2)` pattern with `url(data:font/woff2;base64,<b64>)`.
5. Writes the result as a TypeScript module to `src/plugins/math/katex-css.ts`:

```typescript
// AUTO-GENERATED by scripts/inline-katex-fonts.mjs — DO NOT EDIT MANUALLY
// Regenerate by running: node scripts/inline-katex-fonts.mjs
// KaTeX version: <version from package.json>
export const KATEX_CSS: string = `...patched CSS string...`;
```

**Exact algorithm:**

```javascript
import { readFileSync, readdirSync, writeFileSync } from "fs";
import { resolve, dirname } from "path";
import { fileURLToPath } from "url";

const __dirname = dirname(fileURLToPath(import.meta.url));
const root = resolve(__dirname, "..");
const fontsDir = resolve(root, "node_modules/katex/dist/fonts");
const cssPath  = resolve(root, "node_modules/katex/dist/katex.min.css");
const outPath  = resolve(root, "src/plugins/math/katex-css.ts");

// 1. Build font name → data URI map
const fontMap = new Map();
for (const file of readdirSync(fontsDir)) {
  if (!file.endsWith(".woff2")) continue;
  const b64 = readFileSync(resolve(fontsDir, file)).toString("base64");
  fontMap.set(file, `data:font/woff2;base64,${b64}`);
}

// 2. Read KaTeX CSS
let css = readFileSync(cssPath, "utf8");

// 3. Patch font URLs — matches both url(fonts/foo.woff2) and url(fonts/foo.woff2) format=woff2
css = css.replace(/url\(fonts\/([^)]+\.woff2)\)/g, (_, filename) => {
  const uri = fontMap.get(filename);
  if (!uri) throw new Error(`Font file not found in map: ${filename}`);
  return `url(${uri})`;
});

// 4. Write TypeScript module
const katexVersion = JSON.parse(
  readFileSync(resolve(root, "node_modules/katex/package.json"), "utf8")
).version;

const output = [
  `// AUTO-GENERATED by scripts/inline-katex-fonts.mjs — DO NOT EDIT MANUALLY`,
  `// Regenerate by running: node scripts/inline-katex-fonts.mjs`,
  `// KaTeX version: ${katexVersion}`,
  `export const KATEX_CSS: string = ${JSON.stringify(css)};`,
].join("\n") + "\n";

writeFileSync(outPath, output, "utf8");
console.log(`[inline-katex-fonts] Written: src/plugins/math/katex-css.ts (KaTeX ${katexVersion})`);
```

### 1c. Run the script

```bash
node scripts/inline-katex-fonts.mjs
```

Verify: `src/plugins/math/katex-css.ts` is created, contains `export const KATEX_CSS: string = \`...`, string length is greater than 10,000 characters, file contains embedded `data:font/woff2;base64,` URIs.

### 1d. Add `npm run` script entry

Add to `package.json` `scripts`:

```json
"build:katex-css": "node scripts/inline-katex-fonts.mjs"
```

This makes regeneration discoverable. CI should run it if `package.json` or `node_modules/katex` changes.

### 1e. Create plugin directory skeleton

Create `src/plugins/math/` directory. Create a minimal `math.plugin.ts` that satisfies TypeScript compilation but does nothing:

```typescript
import type { MarkablePluginAPI } from "../markable-plugin-api";

export default {
  id: "math",
  name: "Math",
  version: "1.0.0",
  description: "Render LaTeX math expressions using KaTeX",
  onEnable(_api: MarkablePluginAPI): void {},
  onDisable(_api: MarkablePluginAPI): void {},
};
```

This stub is replaced in step_05. Its purpose is to confirm the plugin entry resolves in the build system.

### 1f. Register plugin in build system

In `scripts/build-plugins.mjs`, add to the `PLUGINS` array:

```javascript
["math", "src/plugins/math/math.plugin.ts"],
```

Position: after the `"yaml-pane"` entry (maintain alphabetical-ish ordering).

### 1g. Verify build

Run: `npm run build:plugins`

Expected: `src-tauri/plugins/core/math.js` is created. No TypeScript errors. KaTeX is bundled into the output (grep `math.js` for `katex` — should find it).

- [ ] `math.js` contains bundled KaTeX JS (contains `renderToString` or similar KaTeX identifier).

## Gotchas: Font URL Patterns

KaTeX CSS uses multiple font URL patterns in the same `@font-face` rule:

```css
src: url(fonts/KaTeX_Main-Regular.woff2) format('woff2'),
     url(fonts/KaTeX_Main-Regular.woff) format('woff'),
     url(fonts/KaTeX_Main-Regular.ttf) format('truetype');
```

The script only needs to patch `.woff2` URLs (the most efficient format, preferred by WebKit). The `.woff` and `.ttf` fallbacks are not patched — WebKit will try `woff2` first and succeed. This keeps the CSS string size manageable.

If a future KaTeX version changes font URL format (e.g., adds `?v=xxx` query parameters), the regex in the script must be updated. The current regex `url\(fonts\/([^)]+\.woff2)\)` handles bare paths only.
