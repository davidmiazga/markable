# Export PDF as 8.5 by 11 pages of the note text, without YAML.

Done means: the fast gate is green and the feature is visible in the profile dev command
Writes: src/, src-tauri/src/, index.html/, flavors/, scripts/, src-tauri/tauri.conf.json/, planning/, tests/
Dev: cd . && npm run tauri dev

## Problem
We want an 8.5x11 page with just the text (not yaml) as the default output.

## In scope
- File → Export → PDF writes US Letter pages: 8.5 by 11 inches.
- A note longer than one page continues on the next letter page. It is not one tall page sized to the note.
- The leading YAML front matter (`---` block at the top) is not in the PDF. The note text after that block is.
- Text sits inside a normal page margin (about 0.75 inch), not against the paper edge.
- This is the only PDF look. There is no page-size picker.

## Out of scope
- HTML export. It still saves the whole note, YAML included.
- Print (Cmd-P). It stays the system print dialog.
- Headers, footers, and page numbers.
- A page-size menu, margins setting, or other paper sizes.
- Changing the save dialog, the suggested filename, or what happens on cancel or a failed write.

## UX / behavior
- Cmd-Alt-E, then PDF, then the save dialog. Same path as now.
- The saved file opens as letter pages of the note text. Properties in the YAML block are not on the page.
- A heading or paragraph in the note body is on the page. A `title:` line inside the YAML block is not.
- A note whose body is empty after the YAML block still saves a PDF: one blank letter page. No error.
- Cancel and a failed write behave as they do now.

## Tests
- The PDF renderer is asked for letter pages, and a rendered page is 8.5 by 11 inches.
- A note that starts with YAML does not put that YAML text in the PDF, and does put the body text in.
- A note with no YAML still exports its text on letter pages.
- HTML export still includes the YAML block.
- Print still calls `window.print` and does not write a PDF.
