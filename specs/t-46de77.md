# Ask or fill direction when a card is unclear

Done means: the fast gate is green and the feature is visible in the profile dev command
Writes: dm-software-machine/
Dev: cd . && npm run tauri dev

Fill every heading below. Replace the HTML comments. Do not leave TODO/TBD.
One-off questions can stay in chat. This file is for a software implementation.

## Problem
If a card does not have enough info or is unclear, the AI can ask questions or take over and put in decent input. It can move the card back to Ready or Blocked so we can work on it.

## In scope
- A thin or unclear card can still be claimed. The agent does not stop at a refusal.
- The agent writes decent Problem, In scope, Out of scope, UX / behavior, and Tests when the card already has enough to choose a direction.
- When the card cannot be carried out without an answer, the agent writes one question on the card and does not invent that answer.
- After asking or filling direction, the agent moves the card to Ready or Blocked and stops. Ready means the direction is on the card for review. Blocked means it is waiting on an answer.
- The question or the one-line direction stays visible on the card.
- A card that already has a complete spec still follows the existing path: implement, Review, then Done when the gate is green.
- If an agent discovers mid-work that the card cannot be carried out, it parks the card on Ready or Blocked instead of finishing.

## Out of scope
- Drawing a new control on the card. The existing reason line is the question.
- Starting this from Markable-Project. The scripts in dm-software-machine do it.
- Filling the five feature cards as part of this ticket. The behavior is available the next time one of those cards is claimed.

## UX / behavior
Move a thin card to Claimed. The pattern shows while the agent is reading it. The agent either fills the spec or leaves one question in the reason. The card then sits on Ready or Blocked with the pattern off. From there the card can be edited and moved again. A complete card moved to Claimed is implemented as before.

## Tests
- A clarify result with no park file and a complete spec lands on Ready with direction on the card.
- A park file of lane blocked lands on Blocked and keeps the question as the reason.
- A park file of lane ready lands on Ready.
- An unknown lane lands on Blocked.
- Claiming a thin card is allowed and marked clarify, instead of a refusal.
