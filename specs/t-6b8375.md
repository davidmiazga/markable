## Problem
FeaturesList checklist marks HTML dashboards open.

NOTE ON DASHBOARDS:
1. Dynamic Live Queries vs. Static/Scripted HTML:
   - _folder.md uses select / view blocks (FROM ., WHERE, SORT, LAYOUT cards|table|list|bookshelf) that automatically query the live Vault Index whenever notes are added, renamed, or re-tagged.
   - A pure dashboard.html written by an AI is infinitely more flexible visually (custom charts, KPIs, timelines, custom JS/CSS), but unless it can query the vault at runtime (e.g., via a small window.markable.getVaultIndex() bridge injected into the iframe), its data is a snapshot from when the AI generated it.
2. Markdown Note Composition vs. Full HTML:
   - _folder.md lets you write normal Markdown prose above/below the dashboard block and edit it inline in Typora mode.
   - dashboard.html is best when the entire tab is an app-like view (like CursorModels-10.18.26.html).
3. Coexistence Option:
They don't necessarily have to conflict: a folder could check for _dashboard.html / dashboard.html (or _folder.md), or any .html file in the vault could simply be runnable as an interactive tab with a window.markable read-only bridge so AI-written HTML dashboards can pull live vault notes/tags/frontmatter on the fly.

A vault keeps a set of files handy. It is not required to open a file. People open notes, HTML, images, and other files from the Open dialog, from a recent file, by dropping a file on the window, or from the file browser when a vault is in use. Markable is part markdown viewer and part browser. A window holds both. A markdown tab is the viewer. An HTML tab is the browser: the page runs, and the host does not reduce it to a static preview. Markable currently answers an HTML open with "Cannot preview this file type," so the file cannot run.

The reference page is this repo's project board, `dm-software-machine/board/project-board.html`, built to `.dm-software-machine/board.html`. In a normal browser a person can drag a card between columns, drop a card onto another card to nest it, edit the card's details, type in the search box and the settings fields, switch Kanban and Table, and download Overrides JSON. The page keeps those edits in `localStorage`. It does not write the task store. An HTML file opened in a Markable tab, and the same file opened in a second Markable window, must keep that kind of page behavior working. The page may read the live vault when one is active, and it may read markdown notes that sit in its own folder. It may not change files.

## In scope
- Opening a file does not require a vault. File Open, Open Recent, a drop onto the window, and a file-browser click all open the chosen file. A missing vault is never the reason an open fails.
- The Open dialog lists Markdown, Text, HTML, and All Files. Any chosen file opens. Markdown and text open in the editor. Images and PDF keep their current viewers. `.html` and `.htm` open as an interactive document tab, including a file that is not inside a vault and including the case where no vault is active. Today that open is a media tab that says "Cannot preview this file type," or the HTML source opened as editor text.
- The file renders in a sandboxed iframe that fills the tab. Inline and relative scripts run. Buttons, forms, text fields, drag and drop, `localStorage`, and a download the page starts all work inside the page. A host sandbox that blocks any of those fails this ticket. The host installs `window.markable` before the page's own scripts run. The iframe cannot reach the editor DOM or call Tauri commands except through the bridge.
- The same HTML file can open in a new Markable window. That window is also part markdown viewer and part browser: the HTML page fills an HTML tab there, and a markdown link from the page opens a markdown tab in that window. The page's drag, edit, storage, and download behavior is the same in the new window as in the first.
- Relative CSS, JS, and images referenced by that HTML file load. A link that resolves to another `.html` or `.htm` file, or to a markdown note, opens that file when the target is inside the active vault or inside the HTML file's own folder. An `http:` or `https:` link opens in the system browser. A `javascript:` link, a `file:` link, or a path that is neither in the vault nor in the HTML file's folder does not open and does not read the target.
- `window.markable.getVaultIndex()` returns the live vault index for markdown notes: `vaultId`, `builtAt`, `capped`, and `entries` of `path`, `name`, `title`, `tags`, `outboundLinks`, `modified`, `size`. The HTML file does not embed a copy of this data.
- `window.markable.getNote(path)` reads one markdown note and returns `{ path, title, tags, frontmatter, body }`. `frontmatter` is the parsed YAML object, including keys other than `title` and `tags`. The stored index only keeps title and tags, so this read is per note, on demand. The note must sit inside the active vault or inside the open HTML file's folder.
- `window.markable.onVaultChange(listener)` runs the listener after the vault index rebuilds (note added, renamed, retagged, or removed) and returns an unsubscribe function.
- The bridge is read-only. It does not write, rename, delete, or invoke other Tauri commands. `getNote` rejects a path that is not markdown, and a path that is neither inside the active vault nor inside the open HTML file's folder, and it does not read that file. With no vault, `getVaultIndex()` returns `entries: []`.
- Opening the same HTML path again activates the existing tab. The tab is part of the saved session and comes back as a running page on the next launch, not as source text and not as the media-preview message.
- Several HTML files can be open beside markdown notes, with or without a vault. Switching tabs shows the page that belongs to that tab.

## Out of scope
- `_folder.md` select / view blocks, and the cards, table, list, and bookshelf layouts. Clicking a folder still opens `_folder.md` when that file exists.
- Treating `_dashboard.html` or `dashboard.html` as the folder's view. A folder does not gain a new click target in this ticket.
- A query language (`FROM`, `WHERE`, `SORT`) inside the HTML page. The page filters `getVaultIndex()` itself.
- Editing the HTML source in the tab, or writing notes from the bridge. A later ticket can add a write bridge if a page needs to save back into the vault.
- Storing every frontmatter key in the persisted vault index.
- A new viewer for PDF, images, or other non-HTML types. Those files still open. PDF and images keep the viewers they already have. A type with no viewer opens a tab that shows "Cannot preview this file type."
- A process that is not a Markable window. "Open in New Window" stays inside Markable.
- Rebuilding the project board, or teaching Markable the board's task schema. The board is only the reference page for browser behavior.

## UX / behavior
- Opening a `.html` or `.htm` file, from the file browser or from any other open path, opens a tab titled with that filename. The page fills the content area. Markable does not add chrome inside the iframe. Dragging, editing fields, switching views, and downloading a file the page creates all happen inside the page and do not change files. No vault has to be active.
- The tab's context menu has "Open in New Window." That opens a Markable window on the same file. Closing the window does not close the tab in the window it came from. Closing the original tab does not close the new window.
- A link inside the page follows the rules in scope: another HTML file becomes a tab, a markdown note opens in the editor, an external web link leaves the app, and a path outside the vault and outside the HTML file's folder is ignored. The ignored click does not show a dialog.
- An empty vault returns `entries: []`. A capped index returns `capped: true` with the notes that were indexed. Neither case is an error dialog.
- `getNote` of a missing markdown path that is allowed (inside the vault, or inside the HTML file's folder) returns null. `getNote` of a path outside both of those, or of a non-markdown path, rejects and leaves the file unread.
- If the HTML file is missing or cannot be read, the tab stays open and shows "Could not load file." plus the path. No second error dialog.
- After quit and relaunch, each HTML tab that was open is open again and its scripts run with a fresh `window.markable`, including an HTML file that is not in a vault.

## Tests
- Opening a `.html` file creates an interactive tab and does not show "Cannot preview this file type." This is true when no vault is active and when the file is outside every vault. A button in that page runs its own script.
- Opening a markdown file, an image, and a file type with no viewer does not require a vault. The image uses its current viewer. The unsupported type shows "Cannot preview this file type." and still opens a tab.
- A fixture page can drag an element into a drop target, edit a text field, read back a `localStorage` value it wrote, and start a download. Those four actions succeed in a Markable HTML tab and again in a second Markable window opened from that tab. `board.html` is the kind of page this fixture stands in for. It does not have to be copied into the app.
- The iframe document exposes `getVaultIndex`, `getNote`, and `onVaultChange` on `window.markable` before the page script runs.
- `getVaultIndex().entries` includes a markdown note created after the HTML file was saved.
- `getNote` returns a frontmatter key other than `title` and `tags` for a note that has one, and returns that note's body.
- `getNote` reads a markdown note that sits in the HTML file's folder when no vault is active. It rejects a path that is outside that folder and outside any vault, and does not read it.
- `onVaultChange` fires after the vault index reloads, and the unsubscribe function stops further calls.
- A relative link to a second HTML file in the same folder opens that file in a second tab when no vault is active. A link to a markdown note in that folder opens the note. An `https:` link is handed to the system browser. A path outside the vault and outside the HTML file's folder does not open and is not read.
- Opening the same HTML path twice leaves one tab. Two different vault HTML files can be open at the same time, and switching tabs shows the matching page.
- Restoring a saved session opens an HTML path as a running page with `window.markable`, not as source text and not as "Cannot preview this file type." A missing vault does not drop that tab.
- A folder that contains `_folder.md` still opens that markdown file when the folder is clicked.
