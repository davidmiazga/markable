## Problem
When categories/tags have similar names - we want to highlight them in red for consolidation. In fact, any of them can be consolidated by pressing on a (gear icon or similar) button. Once clicked, the user is presented with a panel with a field or fields (which in the case of auto detected consolidation is prefilled) containing definitions that will 'merge' into the selected definition. These suggested merges are case-sensitive. Once a field exists, an 'Apply Merge' button is enabled that executes the script that finds the merging field definitions and replaces them with our selected definition.

Adopt next: Merge = rename onto an existing name, extra confirm, no-undo warning

## In scope
Decisions about the merging definition(s) are suggested with a scan script when the gear is clicked. This script is case sensitive and finds categories/tags that are similar in name and/or definition. Common definitions should not slow down the script - the script finds these common terms against a known list ahead of time. Merges are then executed accurately and quickly with another script that is flexible and case-sensitive. Extra UX to handle these merging decisions. We are working with yaml in our notes only.

## Out of scope
Do not change any other systems plugins or functionality. DO not change note content, this is yaml only.

## UX / behavior
Include a panel to handle this change, complete with error states. Errors should include anything that would be considered a special character in the names. Those should be flagged immediately and highlighted for a suggested change that takes out the special character or replaces it with something non-special. Dashes should be ok.
