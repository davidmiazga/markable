Later: Context menu on inline #tags in the editor

Manage already offers search-with and search-without when you right-click a tag in the vocabulary list. A `#tag` written in the body of a note has no menu.

## In scope
Right-click a `#tag` in the open note and get the same two search actions Manage already has. One searches notes that include that tag. The other searches notes that exclude it. The command bar opens with `tag:#name` or `-tag:#name`.

## Out of scope
Rename, merge, nesting, and tag pages stay where they are. Categories and YAML fields are not part of this menu. Other plugins are unchanged except the editor surface that detects the tag under the cursor.

## UX / behavior
Right-clicking `#recipe` in the note body shows "Search notes with this" and "Exclude this from search". The first opens search filled with `tag:#recipe`. The second adds `-tag:#recipe` when a search is already open, and otherwise opens search with only that exclusion. Right-clicking ordinary text does not show this menu. A `#tag` inside a code span is ignored.

## Tests
Run the usual cargo and vite checks. Trigger a right-click on an inline `#tag` and assert the two actions and the query strings. Assert that a right-click on text that is not a tag does not open the menu.
